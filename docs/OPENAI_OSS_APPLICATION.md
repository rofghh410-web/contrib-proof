# Codex for Open Source application preparation

This document is preparation material, not proof of eligibility and not an application submission.

OpenAI's official Codex for Open Source page says the program is intended for core maintainers or widely used public projects. It describes six months of ChatGPT Pro with Codex, conditional Codex Security access, and API credits for eligible maintainer workflows. The terms also say that applications require accurate repository and maintainer information, selection is discretionary, and submission does not guarantee access.

Official references:

- [Codex for Open Source](https://developers.openai.com/community/codex-for-oss)
- [Codex for Open Source Program Terms](https://learn.chatgpt.com/docs/codex-for-oss-terms)

## Do not apply too early

A new repository with no outside users is not automatically a “widely used public project.” The correct path is:

1. publish the repository honestly;
2. keep a visible maintenance history;
3. get real maintainers to run it;
4. merge feedback and document case studies;
5. apply only when the applicant can truthfully describe a core-maintainer role or meaningful ecosystem importance.

Stars alone are not a substitute for adoption, maintenance responsibility, or ecosystem impact.

## Information to collect truthfully

- public repository URL;
- GitHub username and visible contribution history;
- role: primary or core maintainer, if accurate;
- GitHub stars, downloads, dependents, or documented ecosystem importance;
- examples of active issue triage, reviews, releases, or security maintenance;
- OpenAI Organization ID, if requesting API credits;
- a concrete credit budget and workflow plan.

Do not include private credentials, confidential roadmap material, or inflated metrics. Program terms state that application materials are not confidential by default.

## Draft API-credit answer

> Credits would run opt-in maintainer workflows: pull-request evidence reports, issue-intake packets, release-readiness summaries, and explanations of deterministic findings. The default path remains offline and read-only. The model would receive a redacted report rather than a full private checkout; output is advisory and cannot merge, publish, or change a deterministic result. We would publish usage limits, prompts, evaluation cases, and false-positive corrections.

## Acceptance strategy

The strongest application is not “this was generated by Codex.” It is “real maintainers use this, the maintenance responsibility is documented, the workflow is safe, and API credits would expand a proven public-good workflow.”
